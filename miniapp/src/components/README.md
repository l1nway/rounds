## Sheen

The loading placeholder: a `--surface` box with a soft light band sweeping across (`sheen.jsx`, `sheen.css`). Used by the viewer (busy notice and video stage, `features/viewer/README.md`, Loading crossfade) and the filmstrip (`features/timeline/README.md`, Filmstrip cells). Adapted from shelf's `FadeImage` placeholder (`shelf-sharing-webapp/src/app/components/fade.css`, README Fade image): the same 300 %-wide `::before` with a 105° gradient tiled at a third of its width, moved by `translateX(-66.667%)` in 3.6 s (one sweep per 1.8 s, seamless because the tiles repeat).

- Contract: `<Sheen on/>` as a child of a positioned parent with `isolation: isolate`. It sits at `z-index: -1`, so it paints above the parent's background and below the parent's content (the video, the filmstrip cells, the notice text). Without the isolation it falls behind the nearest stacking context's background and disappears.
- Presence: the span exists only while it is needed (`usePresence`, `src/README.md`, Presence; owner rule 2026-10-26, nothing invisible stays mounted). `on` true mounts it and starts the band; `on` false freezes the band (paused, so it does not snap) and fades the layer out (`[data-leaving]`, opacity over `--dur-enter`), then it is unmounted and its `Animation` cancelled. `on` true again during the fade keeps it and resumes the band. Every consumer renders `<Sheen on={…}/>` unconditionally: the component returns nothing while unmounted. A parent that fades out and unmounts itself (the notice) keeps `on` true and takes the sheen with it, so the placeholder does not dim before its parent. The content that replaces it (the video under the stage sheen, the filmstrip cells over theirs) comes in during the same 700 ms (`features/viewer/README.md`, Loading crossfade; `features/timeline/README.md`, Filmstrip cells).
- One duration for all: the old default (stay opaque for `--dur-long`, then `visibility: hidden`) was used only by the notice, while the stage and the filmstrip overrode it with an `--dur-enter` fade. The fade is now the base rule and the overrides are gone.
- Dark theme: the band is `color-mix(in srgb, var(--text) 9%, transparent)` over `--surface`, so it follows the Telegram theme both ways (shelf's literal `#d0d0d0` / `#f6f6f6` were for a light page).
- Motion is WAAPI on the pseudo-element (`animate(…, {pseudoElement: '::before'})`), per perf-web.md: no CSS `@keyframes` iteration events, a compositor-only transform. One `Animation` per mounted span, created in a layout effect, paused / played by `on`, cancelled on unmount. `el.getAnimations()` does not list pseudo-element animations, so the infinite band never holds up the exit. Reduced motion drops the band (`background: none`), leaving a static `--surface` box.
- The element is a `span`, not an `i`: `.timeline-film i` styles the filmstrip cells.

## Slider

Pointer-driven UIKit-style range (`slider.jsx`, `slider.css`, all `.slider*`), owner request 2026-10-27: it replaces the native `input type=range` of the level rows (`features/editor/README.md`, Level rows). A copy of `react-animated-select/apps/demo/src/components/slider.jsx` (its README, Slider) adapted for Preact; the owner chose a copy over a shared package for now, so a fix in one is not in the other.

- Contract: `<Slider value min max step origin locked disabled reset onChange onDrag aria-*/>`. `onChange(number)` only when the snapped value changes (not per `pointermove`), always clamped to `[min, max]`, rounded to 6 decimals against float drift (`0.1 × 3`). `onDrag(true)` on press, `onDrag(false)` on release or cancel; keyboard changes never call it, each key is a finished change. `origin`: where the fill starts (0 of a centred slider), default `min`. `reset`: a double tap (two taps under 8 px of movement within `DOUBLE` 350 ms) sets `origin`. `locked`: presses and keys are ignored, the thumb shrinks and the fill dims (`[data-locked]`), the row stays at full opacity; `disabled`: the same plus `aria-disabled` on the container, which the consumer dims. Other props (`aria-label`, `aria-valuetext`, `aria-busy`) land on the thumb (`role='slider'`).
- Colours come from the Telegram theme only: fill `--button`, thumb `--on-stage`; `--track` (unfilled part) and `--knob` (thumb shadow) are set by the consumer (`.options`), shared with the switch. The `--boing` overshoot curve is the source's.
- Geometry: 28 px tall hit area (the thumb), 14 px side padding so the thumb at either end stays inside the row; the track is 4 px. Fill: `inset` from `--lo` to `--hi` (min / max of the value and `origin` in percent), so a centred slider fills from the middle either way. No `abs()` (Chrome 138).
- Changes against the source: pointer capture on the container plus `pointercancel` instead of document listeners (the source never cleaned up on a cancelled touch: an iOS scroll takeover left its listeners alive until the next `pointerup`); the whole 28 px row is the hit area (the source's was the 0.4 em track); press scale 1.15 (1.3 read too big at 28 px); one `loop` runner for the press and the release spring, one `requestAnimationFrame` at a time, cancelled on unmount.
- Drag: the thumb's inline `left: 0` and a per-frame `transform` (no layout per frame, no React render per frame: the visual state lives in a ref). Values are committed from x only; the 2-D rubber band past the ends is visual (Slider stretch). After release a spring settles the thumb on the snapped value, then the inline styles are cleared and CSS `left: var(--progress)` takes over again. Keyboard changes move it by the CSS transition.
- `prefers-reduced-motion` turns the CSS transitions off; the drag spring still runs (same as the source).

## Slider stretch

The overdrag squash in `render()`: the pull vector past the track end goes through the iOS rubber-band curve (`PULL` 15 px asymptote) and stretches the thumb along it by up to 25 % and squeezes it across by up to 17.5 %, as one `matrix()`. Tuned in the source by eye; kept as is.
