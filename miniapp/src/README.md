# src

## Theme tokens

The colour tokens live in the inline `<style>` of `miniapp/index.html`, the only place with hex values (checked with a grep 2026-10-26; the white of marks, playhead and switch thumb reads `--on-stage`); `index.css` holds the other tokens (`--radius`, `--control`, motion) and must not redefine a colour. The inline style maps Telegram's theme variables onto the app tokens (`--bg`, `--surface`, `--text`, `--hint`, `--link`, `--button`, `--button-text`, `--danger`), sets `color-scheme` from `--tg-color-scheme` (native controls and scrollbars match) and paints `html` with `--bg` / `--text`. The second argument of each `var()` is the fallback for a browser outside Telegram and for the dev mock, redefined under `prefers-color-scheme: dark`; inside Telegram the Telegram colours always win, whatever the OS theme.

Why inline in `index.html` (owner request 2026-10-26, a white flash on reload): `vite dev` injects `index.css` from JS, so before the module script ran the first paint had no CSS at all. Measured in headless Edge, dev server, the module scripts held back 5 s: the first paint was `#fff` in the dark scheme, and a screencast of a reload in the dark scheme showed one white frame between the old page and the dark one (the owner saw two in Edge, one in Firefox). With the tokens inline, the first paint is `#1c1c1d` dark / `#fff` light, `#17212b` with Telegram theme params in the hash, and the reload screencast has no white frame (3 runs). The build was already right (the inlined CSS is in `<head>`), so this fixes dev and keeps the build. `<meta name='color-scheme'>` was not added: the inline `:root` already sets `color-scheme` before the first paint and would override the meta anyway.

The Telegram script sets `--tg-theme-*` and `--tg-color-scheme` on `<html>` synchronously while it runs: `telegram-web-app.js?64` reads `tgWebAppThemeParams` from the URL hash (or `sessionStorage` after a reload) at load and calls `setThemeParams`, which writes each colour through `document.documentElement.style.setProperty('--tg-…')` (read 2026-10-26), and keeps them current on `theme_changed`. It is a parser-blocking script in `<head>`, so the variables exist before the first paint (observed: `--tg-theme-bg-color` set while the module script was still held back). JS reads only `themeParams.button_color` (Mono accent).

## Mono accent

[DOC: mono-accent] Owner 2026-10-30: Telegram's stock blue looked cheap ("Material UI on Android"). Without a theme of the user's own the accent is monochrome, like Apple's apps; a theme of the user's own keeps its colours.

- `data-mono` on `<html>` switches it. The launch router in `index.html` sets it for the browser version (no Telegram theme exists there). In the Mini App `setupTelegram` (`services/telegram.js`) sets it when `button_color` is a stock Telegram blue, and again on `themeChanged`.
- Stock blue is a hue band, not a list: blue the largest channel, hue about 200°–220° (`(g − r) / (b − r)` between 1/3 and 3/4), saturation over 0.4. It catches `#2481cc`, `#3e88f7`, `#40a7e3`, `#5288c1`, `#50a8eb`, `#007aff` (checked by hand). These are Telegram's defaults on Android, Desktop and iOS as remembered, not re-verified against each client. Telegram tells a Mini App nothing about whether the theme is the default one. A user's own theme in that same blue band also goes mono, deliberately.
- Mono tokens, in the `:root[data-mono]` rule:
  - `--button` / `--link` = `--text`, `--button-text` = `--bg`: black on light, white on dark;
  - `--toggle` = iOS system green (`#34c759` / `#30d158`), as the default UISwitch has it;
  - `--segment` / `--segment-text` = the native UISegmentedControl's white thumb (light) or `#636366` thumb (dark), with `--text`.
  - Light and dark come from `light-dark()`, so they follow Telegram's scheme, not the OS.
- Inside `.viewer` (always the black stage) mono `--button` is `--on-stage` white with `--stage` text, like the Camera app. Otherwise a black button would vanish on the stage in the light theme. As a result the selection point is a plain white dot, and its busy pulse (a mix with white) does not show; the ring around it still shows the work.
- Without mono, `--toggle` and `--segment` are `--button` and `--segment-text` is `--button-text`, so a user's theme looks as it did before.
- The browser cannot take the user's Telegram theme after sign-in: the OIDC / Login Widget data are id, name, username and photo. This is from Telegram's docs as remembered, not re-checked on 2026-10-30. No Bot API method returns a user's theme either.

Fixed colours: `--stage` (black behind the video in both themes, with `--on-stage` white for text and marks on it, the playhead and the switch thumb, which is white in both iOS themes), `--trim` (iOS yellow trim frame). Literal `rgb(0 0 0 / a)` shadows and scrims and the lift's white glows (`lift.css`, its own variables) are the only other colours: they darken or light whatever video is under them, the same in both themes. Every other colour comes from the Telegram theme. Motion: every transition reads `--dur` / `--ease`; `prefers-reduced-motion` sets `--dur: 0ms`, so state changes still happen, just without the tween.

## Radius scale

[DOC: radius-scale] Owner request 2026-10-29: one corner pattern, Apple-like, instead of 4, 6, 7, 9 and 12 px picked per component. Four tokens in `index.css`: `--radius-s` 8 px (small surfaces inside a control or a frame: the filmstrip, its shades and handles, the selection box), `--radius` 12 px (controls: buttons, the segmented control, notices, the files list), `--radius-l` 22 px (cards and sheets: the browser version's modal card), `--pill` 999 px (pills: the point's tag and its buttons, badges, switches). Circles stay `50%`. Nested shapes are concentric: the inner radius is the outer one minus the gap (`--inner: calc(var(--radius) - 2px)` of the codec thumb). Tiny marks (1 to 3 px bars and handles) keep their own values: they are lines, not surfaces.

## Springs

[DOC: springs] Two spring curves as `linear()` tokens in `index.css`, sampled from a damped spring (`x(t) = 1 − e^(−ζωt)(cos ω_d t + ζω/ω_d sin ω_d t)`, 33 points): `--spring` (ζ 0.75, about 3 % overshoot: the codec thumb, the modal card, presses) and `--spring-pop` (ζ 0.6, about 9 %: things that appear from nothing, the point, its ring and pill, "from 0 to 1.1 and back to 1", owner 2026-10-29). Both with `--dur-spring` (560 ms, 0 under reduced motion). An exit never uses them: overshooting on the way out looks like a bounce back. `linear()` needs Safari 17.2, Chrome 113, Firefox 112, inside the build target (`miniapp/README.md`, Build target).

## Document scroll

The document is the page's only scroller; `#root` has no height rule. `html` has `scrollbar-gutter: stable`, so a classic Windows scrollbar never narrows the layout and `100cqw` of the editor stays its content width (`features/editor/README.md`, Editor scroll, which also says why an inner scroller broke iOS).

## Reset

`@layer reset` at the top of `index.css`, written for the elements the app renders (`main`, `form`, `section`, `div`, `span`, `i`, `p`, `small`, `h1` (the browser sign-in, 2026-10-27), `h2`, `label`, `input` checkbox / radio, `button`, `output`, `video`, `canvas`, `img`, `svg`; checked with a grep of `src/` on 2026-10-26; `img` added with the exact look frame the same day), so UA styles change nothing:

- `box-sizing: border-box` on every element and pseudo-element: a `width` / `height` / `min-height` is the outer size, padding and border included.
- No UA margins (`body`, `h1`, `h2`, `p`, `input`, `button`; `form` has none in standards mode), no `button` padding / border / background; `h1`, `h2` and `small` inherit the font size (headings keep the UA bold); `button` and `input` inherit font, colour and letter spacing; `video`, `canvas`, `svg`, `img` are blocks capped at `max-width: 100%`; `-webkit-text-size-adjust: 100%` and no tap highlight.
- Why a layer: unlayered rules always beat layered ones whatever the specificity or order, so any component rule wins over the reset, and the reset cannot win over a component rule by accident.
- Do not re-add these resets in component CSS (`margin: 0` on `p` / `h2` / `input`, `border: 0` / `padding: 0` / `background` on a `button`, `font: inherit` / `color: inherit` on controls). A component sets only what it changes. `appearance: none` on the switch is the switch's own design, not a reset.
- Under border-box a component that sets a size together with padding or border sets the outer size: `.spinner` is 34 px (28 + 2 × 3 px border before the reset), and a `min-height` that must clear padding adds it (`calc(var(--control) + 12px)`).
- A new element type (a `ul`, a text `input`, a `fieldset`, an `h1`) gets its reset here when it is first used, nothing preemptive.

## Motion tokens

`--dur-long` (400 ms, 0 under reduced motion) is for crossfades and the switch spring; `--dur` stays for small state changes. `@keyframes appear` (`from {opacity: 0}`) is the plain reveal, used by the video and marks. `@keyframes leave` is the shared exit of Swap and Presence (below). `@keyframes enter` (`from {opacity: 0; filter: blur(10px); scale: 1.06}`, `--dur-enter` 700 ms, 0 under reduced motion) is the soft reveal of the entrance and of the filmstrip cells.

## Presence

Owner rule 2026-10-26: whatever disappears is unmounted, nothing invisible stays in the DOM. `usePresence(show)` in `hooks/state.js` returns `[mounted, ref]`: the consumer renders `{mounted && <el ref={ref}/>}`; when `show` turns false the hook sets `data-leaving` on the element, waits for every finite animation and transition on it (`getAnimations()`, infinite ones such as a spinner are skipped), then unmounts. The exit itself is the element's own CSS under `[data-leaving]` (a `leave` animation or a transition to `opacity: 0`); without such a rule the element goes at once. `show` turning true again during the exit keeps the element and drops `data-leaving`. Reduced motion zeroes `--dur` / `--dur-long`, so exits end on the next frame. `getAnimations()` flushes pending style first (Web Animations, `Animatable.getAnimations`), so the animation started by `data-leaving` is in the list.

- `leave(el)` waits until no finite animation on the element is still running: it awaits them with `allSettled` and checks again. It used to `Promise.all` the `finished` promises, and a cancelled animation (a style change that replaces a running transition, an attribute removed mid-animation) rejected it, so the element was never unmounted and stayed invisible in the DOM.
- `useLeave(on, done)` is the building block: it returns a ref and, when `on` turns false, runs `leave` on that element and then calls `done` (stable, or the exit restarts). `usePresence` is `useLeave` plus a `mounted` state. Lists whose items leave on their own (Swap items, the Lift layers in `features/viewer/lift.jsx`) use `useLeave` per item and drop the item from their state in `done`.
- Element animations only: `el.getAnimations()` does not list animations of its pseudo-elements, so a WAAPI band on `::before` (Sheen) never holds up an exit.

- What appears is reserved by the layout around it when it must not shift rows (a `min-height` on the parent), never by an invisible element.
- The element must not be shared with a ref of another hook; one `usePresence` per element.

## Swap

`components/swap.jsx`: `<Swap as='small' text={…}/>` shows a text that changes with an animated swap (owner request 2026-10-26): the old text leaves (`leave`: fade, `blur(6px)`, scale down to 0.9, `--dur`) and is unmounted, the new one enters in the same grid cell (`enter`, `--dur-long`). The text present at the first render does not animate (`data-still`: it comes with its block's entrance). An empty text lets the last one leave, and once nothing is left the container itself is unmounted (`null`), so an empty status line takes no node. The container gets `data-swap` (`display: grid`, styles in `index.css`); the items are `span.swap` with `width: fit-content`, so the scale origin is the text's own centre. When texts of different widths overlap during a swap the container is as wide as the widest, and the items sit at its start: a centred line needs `justify-items: center` on the container (the timeline mode line, the viewer notice), or the remaining text shifts when the wider one leaves. Rest props go to the container (`role`, `className`, `aria-live`).

- Blocks: `item` sets the item tag (`'span'` by default) and `children`, if given, is a render function called with the swapped value for every item, leaving ones included, so a leaving item keeps rendering with live state. `text` is then any value compared by identity, not only a string: the viewer notice passes the notice object (`<Swap as='div' item='div' text={shown}>{n => …}</Swap>`, `features/viewer/README.md`, Loading crossfade).
- [DOC: swap-resize] `resize` (opt-in) animates the container's width whenever the item list changes, so a pill around the text (the point's tag, `features/viewer/README.md`, AI progress) does not snap when the wider old text unmounts or a wider new one mounts (owner 2026-10-29, iPhone SE2: "Downloading selection model… 91 %" to "Selecting object…" collapsed at once). WAAPI `width` from the last width, or from the current animated width when a resize is still running, to the new natural width, `400 ms` with the `--ease` curve. Measuring needs the container's own animations cancelled first (`getAnimations()` is the element's own, not the subtree's). The tag clips horizontally (`overflow-x: clip` on `.viewer-tag-body`) so a growing text does not stick out of the pill. Off for full-width lines, where the width never changes.

## Entrance

Owner request 2026-10-26 (recording `IMG_0407.MP4`, iPhone SE2): after Telegram's sheet expanded to fullscreen every block popped in at once. Now the blocks come in one after another, each from transparent, blurred and scaled 1.06 to normal, like the staggered entrance of shelf-sharing-webapp (`src/app/README.md`, Entrance animation) but softer (no overshoot, 700 ms, `--ease`).

- Contract: a block gets the class `enter` and its place `--i` in its own CSS; the delay is `--i × --stagger` (110 ms). Order: viewer (0, `.viewer`), timeline strip with its head (1, `.timeline-head`, `.timeline-track`), the play and frame buttons (2, `.timeline-controls`), then the options from step 3 (`FIRST_OPTION` in `features/editor/options.jsx`): the codec row, which is there from the first render. The option rows and the status line mount with the job, usually after the cascade has run; they then take steps counted from their own mount, and only a job that arrives before `data-enter` puts the rows into the cascade proper, before the codec (`features/editor/README.md`, Late rows). Blocks with the same `--i` move together. Owner request 2026-10-26 (`IMG_0409.MP4`): the options block came in as one piece, the rows should come one by one. The submit bar is not part of the cascade: it mounts when the video has loaded and plays `enter` at once (`features/editor/README.md`, Submit bar).
- Gate: until `<html>` has `data-enter` every `.enter` is `opacity: 0`; then the animation runs with `backwards` fill, so nothing is left hidden after it. `services/telegram.js` sets the attribute once Telegram finished expanding (`services/README.md`, Entrance), so the cascade plays on the settled, full-size layout instead of under the expand animation. Outside Telegram and in the mock it is set at once.
- Reduced motion: no hiding and no animation (both rules sit inside `prefers-reduced-motion: no-preference`).
- Cost: `filter` and `scale` only (no layout); four blocks for under a second, once per open. Checked in the mock (Edge headless, 375 × 667, dark, CPU ×4, slow 4G, CDP screencast): the four steps and the filmstrip wave play in order; perf harness unchanged (CLS 0.000, M LCP 2568 ms against 2572 before, Entry 16.4 KB). The feel on the iPhone is for the owner to judge.
- The grey sheet with the Telegram icon before the page (about 2 s in the recording) and its jump to black are Telegram's own loading screen, not the page: its colours and icon are set in @BotFather (Bot Settings → Configure Mini App, loading screen; Bot API 8.0). Matching its dark background to the dark `bg_color` removes the jump.
