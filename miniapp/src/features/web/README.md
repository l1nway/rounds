# web

The browser version's shell (`web-app.jsx`, `result.jsx`, `web.css`): the same editor as the Mini App (`features/editor`) with a local file instead of a server job. Imported only by `src/web.jsx`; `web.css` goes in through `?inline` (`miniapp/README.md`, Inline CSS). Owner decision 2026-10-28: no separate web page; three levels in one editor: anonymous (`local`: whatever the device can do, the round is downloaded), signed in (`free`: plus Oracle, plus sending to the chat), signed in and in `ALLOWED_USER_IDS` (`pro`: plus Modal). Executor priority: device, then Oracle, then Modal (`features/local/README.md`, Local plan).

## Web shell

`WebApp` builds a job from the dropped file: `{id: null, status: 'ready', max_duration: 60, request: null, tier, local: true, lift, follow, file, name, size, meta, proxy_url (blob URL), filmstrip_url, filmstrip}`. `id: null` keeps server-bound viewer features off while `lift` and `follow` run tap-to-lift and video tracking locally (`features/local/README.md`, Local lift, Local tracking; for a `pro` user whose promoted `source.id` is ready, local failure falls back to `POST /api/jobs/:id/segment` and `POST /api/jobs/:id/track`); `tier` is `local` without a session, else the session's `user.tier` (`account/session.js`, `tierOf`). Nothing is shown but the viewer's notice until a file is loaded, like the Mini App while its job loads; the notice carries `local: true` so its button works offline (`viewer.jsx` disables a notice action offline otherwise).

- [DOC: web-local-ai] `lift` and `follow` are built inside the job's `useMemo` by one helper (`local(load, kind, route)`), called by the viewer as `(want, report)`: lazy-load the module, pass `confirm(kind)` (the consent card, Web consent) and turn the model download share, the preparation share (`onReady`, `onPrepare`, `onLoaded`, `features/local/README.md`, Model prepare) and the tracking share into `report({label, share})` with the three `LABELS` of that kind (downloading, preparing, busy); the viewer draws it on the point (`viewer/README.md`, AI progress). There is no `.web-sync` line any more (owner 2026-10-29). `follow.stop` aborts a local preview track (`viewer/README.md`, Follow confirm). For `pro` with a promoted `source.id` fall back to the server route (`segment`, `track`) on a local failure. `lift` and `follow` run inside `awake` (a screen Wake Lock, `features/local/README.md`, Local awake), as does the render (its card shows "Following the object…" during the tracking stage, `features/local/README.md`, Render progress); `follow` always exists (no feature is ever switched off after a crash, Track guard); with WebGPU it is fast, without it it runs on the CPU (slow, same memory rules).
- Signing in or out changes `tier`, so the job object is rebuilt and `Editor` resets its draft (it reinitialises on job identity) unless the job carries `resume` (Web promote): a local-only job still loses the trim and selection, do it before them. Keying the effect on `job?.meta` worked but oxlint's `exhaustive-deps` warns about it.
- Replacing the file: a new drop revokes the old blob URLs and re-probes; a result card open or a render running blocks it.
- Automatic server fallback on probe failure: when local probe fails (e.g. unsupported codec like ProRes or corrupted stream) and the user is signed in (`user != null`, online, `<= 2000 MB`), the shell skips the blocking error and immediately hands the file over to server preparation (`prepare(file, say, tier !== 'pro')` via Oracle or Modal), where FFmpeg generates the proxy video and filmstrip.

## Web drop

The drop zone is the whole `.viewer` (owner): the wrapper handles `dragover` / `drop` for anything carrying files, always calling `preventDefault` (a drop outside the viewer must not make the browser open the file) and accepting the file only when the event target is inside `.viewer`; the viewer gets an inset ring while a file is over it (`data-over`). A click on the empty viewer's "Choose a video" button opens the file input (`accept='video/*'`, but a file with an empty `type` is still tried: the probe decides). The input is held in state, not a ref, because oxlint's `react(refs)` rule flags a ref read inside a callback that ends up in the rendered notice.

## Web result

A modal card over the editor (`result.jsx`): grows out of what opened it and shrinks back into it over a dimmed, blurred backdrop (Web morph); while the work runs, its text and progress (rendering, uploading); when a local AI model needs a first-use download (`consent`, `features/local/README.md`, Local models), a confirmation card (Web consent), followed by byte progress on the point (`viewer/README.md`, AI progress); afterwards, for a local round, a looping preview in a circle (a tap toggles sound), the size, Download (`<a download>` of the blob URL), Send to Telegram for a signed-in user (`POST /api/notes`; `held: true` in the answer means Telegram refused because the user restricts voice and video messages, and the card says to allow the bot and press Resend in the chat) and Another video / Close; for the server path, only the "sent to the server, the round arrives in your chat" line. When Modal was unavailable and the round was made on Oracle instead, the status line says so and lists what was left out (`dropped`, `features/local/README.md`, Modal fallback). A failure goes to the editor's own error line (the shell rethrows from `send`), so it is announced like a Mini App error.

## Web morph

Owner request 2026-10-29, reworked the same day after the iPhone recording `IMG_04161.MP4` ("a rectangle appears from nowhere and the text is spat out"): the card grows out of what opened it, like a shared element transition, and shrinks back into it. Everything is WAAPI in `morph.js` (`useMorph`, `useScrim`); `result.jsx` only says where each card comes from (`ORIGINS`, a list of selectors tried in order: the tapped point or the box for the selection model, the Follow pill then the point for the tracking model, the Make round button for work and result; the crash card has none).

- Grow (`GROW` 640 ms, `--spring` from `index.css`, about 3 % overshoot): the card is laid out at its real size and animated by `transform: translate` (from the origin's centre) plus `clip-path: inset(... round r)`, never `scale`, so the text inside is never squeezed. Its fill starts as the origin's colour (the blue point) and turns into the card's own in 300 ms (`TINT`).
- [DOC: web-morph-circle] A circular origin passes through a middle keyframe (`ROUND` 0.38 of the way): a circle of 0.6 × the card's short side (`CIRCLE`), 40 % of the way from the point (`TRAVEL`). Without it the radius grew linearly from 11 to 22 px while the size grew 15 times, so the dot turned into a square almost at once (filmed frame by frame in headless Edge). A rounded-rectangle origin (the button, another card) goes straight to the card.
- Content: every child of the card fades and rises in (`LIFT`: opacity, 12 px, 0.97, a 6 px blur) from 32 % of the grow (`REVEAL`, "halfway"), 50 ms apart (`STAGGER`).
- [DOC: web-morph-scrim] Dim, blur and transparency are one layer: `.web-backdrop::before` holds the tint and `backdrop-filter: blur(18px) saturate(1.4)` at full strength and only its `opacity` is animated (WAAPI with `pseudoElement: '::before'`), by `useScrim` in `Result` with the card's duration and Apple's sheet curve (`SETTLE`). Animating the blur radius itself (the old `web-backdrop-enter`) and running it on a 300 ms CSS transition beside a 480 ms card is what looked torn. The backdrop element lives in `Result`, not in each card, so switching cards (work → result) does not flash the scrim.
- Leave: the current animated values are read (`getComputedStyle`), the running animations cancelled, the content fades in 140 ms, and the card goes from where it is now through the circle back into the origin, measured again (the point may have moved), with an accelerating curve (`EXIT`, `SHRINK` 380 ms) while its fill turns back into the origin's colour; the scrim fades over the same 380 ms. So a card closed halfway through its grow reverses from that point without a jump. `usePresence`'s ref sits on the card (`host` in `result.jsx`), so the unmount waits for the card's own animations; `data-closing` on the backdrop stops it from catching taps meanwhile.
- [DOC: web-morph-handoff] When one card replaces another while open (work → result, consent → work), the old card's cleanup stores its box (`handoff`, module state in `morph.js`, one modal host) and the new card grows from it instead of from the origin. `Result` clears it once nothing is mounted.
- No origin on screen or reduced motion: a plain fade and scale (0 ms with reduced motion).

## Web consent

[DOC: web-consent] The model download card says what is downloaded and why (owner 2026-10-29): per kind (`lift`, `follow`, from `confirm(kind)` in the shell) a title, what the model does for the user, the files with their sizes (`models` from `loadModels`, names mapped by `PARTS`), the model and its origin from the first file's `credit` (`local/weights.js`: SAM 2.1 Tiny, or EdgeSAM with its non-commercial licence on touch devices, `local/README.md`, Lift model), "from Hugging Face", the total, and that it runs on the device and stays cached for offline use. Consent is per model now (`approved` is a set of names in `local/models.js`), so the tracking model asks on its own instead of riding on the selection model's yes.

## Web crash

[DOC: web-crash] After the tab died during a model call (Safari reloads it; `crashed` from `local/models.js`, `features/local/README.md`, Track guard), the shell imports `models.js` on mount and opens a crash card in `Result` (`crash: 'gpu' | 'wasm'`, before work and result, after consent). Owner 2026-10-29: never slow the work down behind the user's back, offer it. The card is one title ("The page restarted") and one sentence (owner 2026-10-29: the first version with a list of tips was too wordy). After a `gpu` crash the sentence says it was most likely memory and offers "Use the processor" (`preferCpu()`, for this tab) or "Keep the graphics card"; after a `wasm` crash it says to close other apps and tabs, with OK. The private-tab tip was dropped: that Private Browsing keeps the Cache API (the models included) in memory is reasoned from WebKit's ephemeral sessions, not measured. The memory cause is confirmed by jetsam logs from both the SE2 and the XR (`highwater` at about 1.54 GB, `BUGS.md`, iPhone reload on tracking; `features/local/README.md`, gpu-buffer-cache), but a reload can have other causes, so "usually" is deliberate.

- Safari's own "Reduce Protections" banner after the reload (owner, iPhone SE2) is its generic prompt for Advanced Fingerprinting Protection, which Private Browsing turns on; it does not touch memory, so the card does not send users there.
- No origin for the morph (nothing opened the card), so it uses the plain CSS enter.

## Web same render

[DOC: web-same-render] `send` remembers the last finished render (`last`: the file, `JSON.stringify(body)`, and the result: the blob, or `remote`). Make round with the same file and the same body shows that result again (a new blob URL, `again: true`, a line saying nothing was rendered twice; for the server path "Already sent with these settings") instead of rendering again. With the editor's submit lock and the server's dedupe (`editor/README.md`, Submit lock) one round is never made twice by accident. Any change of the body renders again.

## Web promote

For a `pro` user the file is also uploaded in the background (`prepare`, `local/server.js`) as soon as it is probed. When the server job is ready the shell swaps the job: the server's `id`, proxy, filmstrip and `meta` (the local `off` and `hdr` kept) with the same file, so tap-to-lift, tracking and the HDR preview work on a local file. A swap would reset the draft, so the new job carries `resume`, a patch function `Editor` dispatches instead of `init(job)` (it also skips the seek): range, selection, options, levels and codec are kept, new rows come from the server meta. It is built in the shell (`CARRY`), not in `editor/draft.js`, so the Mini App does not carry it. It runs silently (the `.web-sync` line was removed, owner 2026-10-29); a failure goes to `console.warn` in development only and leaves the local job working without server tools, and Make round uploads again when it needs Modal. When the local probe fails and the file goes to the server instead, the upload text replaces the "Preparing the video…" notice's text.

- [DOC: modal-fallback] An upload that the router answered from Oracle (Modal down) counts as a failed promotion: an Oracle job has no `segment` / `track` (`features/local/README.md`, Modal fallback).
- Not for a file over 2000 MB or while offline. The effect is keyed on `[tier, source]`: signing in later promotes a file that is already loaded; a new file makes the running upload's result be ignored (the upload itself is not aborted).
- On Make round, a render that needs Modal (`needsModal`) uses the promoted job (it waits for the upload still running, or uploads fresh if that failed). A render that needs the server but not Modal (no selection follow, no pro option) goes to Oracle through a second upload with `?via=oracle` (Oracle first, owner 2026-10-28): the promoted Modal job cannot be rendered by Oracle, they share no files.
- Retry: after a failed Make round the button reads Retry (the `retry` prop of `Editor`, passed only here; the same submit runs again), and the result card's Send button reads Retry after a refused or failed send.
