# editor

The editing screen: composes `viewer`, `timeline` and the options, owns the draft and the submit. `app.jsx` renders it for every state (with `job` null while loading) so the loading, ingesting and error screens are the same layout as the ready one (layout stability).

## Editor draft

One `useReducer(merge)` holds what the owner picks: `start`, `end`, `time` (the frame of the selection, `prompt.time`), `points` (`[x, y, label]`, label 1 = this; 0 = not this exists in the API but the UI no longer places it, `viewer/README.md`), `box` (`[x0, y0, x1, y1]`), `mask` (the lifted outline the tracker follows, a PNG data URL, null without one, `viewer/README.md`, Lift), `options`, `posting`, `error`. It starts empty (`job` is null on the first render) and is filled once, from `job.request` (the previous submission) or from defaults (`0 … min(duration, max_duration)`), by a layout effect on `[job]` that also seeks to the selection frame. `useJob` never refetches a settled job, so `job` changes identity once (null → job) and the draft is never reset by the network. The editor is deliberately **not** keyed by job id any more (it was until 2026-10-26): a remount recreated every element, so nothing could animate from the loading state into the loaded one (the switches snapped on, the trim frame popped in), and the MainButton cleanup `hide()` of the old instance plus `show` of the new one made Telegram iOS slide the button out and back in (recording `IMG_0406.MP4`, 4.0 s). The layout effect runs before paint, so the one render with the job and the empty draft is never shown. The status line text is a keyed `span` inside the persistent live-region `p` (a new text fades in, `appear`; the live region itself is never remounted, which would break announcements). Children get `dispatch` and patch the fields they own; the clamps live where the gesture happens (`timeline`, Trim bounds), validation here (`isValid`: a positive point or a box, `MIN_RANGE ≤ end − start ≤ max_duration`, `start ≤ time ≤ end`).

States by `job.status`: `ready` edits; `done` / `failed` edit a prefilled draft and say so in the status line (resubmitting is allowed); `rendering` is read-only (no handles, no marks input, options disabled, MainButton hidden) but scrubbing still works to look at the submitted selection. After a successful POST: haptic success and `Telegram.WebApp.close()`; the bot reports progress in the chat. The status line holds one line: an error (`role='alert'`) or a note (`role='status'`), keep notes short enough for 320 px.

## Render boundaries

The draft lives in the editor, so every draft change renders `Editor`; the children are `memo` and get only what they read, so a change reaches only its consumers. `Viewer` gets `selection` (`time`, `points`, `box`, one `useMemo` object), `Timeline` gets `start` / `end` / `time`, `Options` gets `options`. A trim drag (a `dispatch` per pointer move) therefore renders `Editor` + `Timeline` only, a tap on the video `Editor` + `Viewer` + `Marks`. The playhead never goes through the draft: `time` of the player store is read by `Clock`, `Scrub` and the boolean `useAway` selector (`hooks/player.js`, shared by `Marks` and `Lift`). `Editor` itself is `memo` because `useJob` re-renders `App` on every poll while ingesting (`job` stays null, `notice` is a constant). Do not pass `draft` or an inline object to a child: it defeats the `memo`. Reasoned from the props, not counted with the Profiler.

## Options seam

`OPTIONS` is the list of render options: `key` (the field in `options` sent to `POST /render`), `label`, `hint`, `needs(meta)` and the text shown when the video cannot have it. A new option (stabilization, audio filters) is one more entry plus the backend field; the switch row, defaults (`false`) and the payload (`optionsFor`, which forces an unavailable option to `false`) follow from the list. A row is disabled, not hidden, when `needs` fails (no audio for loudness), so the layout does not change between videos. `interpolate` ("Smooth to 60 fps") reads `meta.interpolable`, which the backend decides at ingest (`backend/rounds/README.md`, Output rate); jobs ingested before the field have it undefined, so the row is disabled for them. `metadata` ("Keep original metadata") reads `meta.tags` (the source tags the note can carry, `backend/rounds/README.md`, Note metadata): enabled when it has at least one key, disabled for jobs ingested before the field. Its hint must keep saying that the location travels with the note (privacy: the owner sends notes to other people). The `hires` switch (up to 1080 px) was removed on 2026-10-26: Telegram delivered a 1080 note as a regular video (`backend/rounds/README.md`, High resolution); the backend ignores the key in old requests. The mock job (`scripts/mock-media.mjs`, 1920×1080 with Apple-style `tags`) enables every row; rerun `npm run mock` after changing its `meta`.

## Safe areas

`.editor` pads itself with `max(env(safe-area-inset-*), var(--tg-safe-area-inset-*))` plus `--tg-content-safe-area-inset-*` (Telegram's own controls over the page in fullscreen, Bot API 8.0). The Telegram script sets those variables and updates them on `safeAreaChanged` / `contentSafeAreaChanged`; outside fullscreen they are 0. `env()` is used only as padding of this element (web-platforms.md: it is not a stable number on iOS). Not verified on a phone: whether the MainButton's bottom bar overlaps the page in fullscreen (then `--tg-content-safe-area-inset-bottom` would carry it).

## Editor scroll

`.editor` is a size container (`container-type: size`, its `cqh` is what the viewer's 70 % reads) and scrolls vertically (`overflow: hidden auto`). Before the job the rows are `minmax(0, 1fr) auto auto auto` (the viewer takes the leftover); with `.viewer[data-fit]` they become `auto auto auto 1fr` (`viewer/README.md`, Viewer fit), and on a short screen the options go below the fold: on the iPhone SE2 with a vertical video 191 px. Owner decision 2026-10-26: scroll, never compress the options (an overlay menu may come later).

- A scroll can start only where the page does not own the gesture: the viewer input, the timeline track and the switches are `touch-action: none`, so the user swipes on the time labels, the play / frame buttons, the option text or the black letterbox bars outside the stage. Checked with raw CDP touch events in Edge (375 × 667): a swipe from the buttons and the time labels scrolls to the end; `Input.synthesizeScrollGesture` does not scroll this element in headless Edge, so do not use it as a test.
- The MainButton is Telegram's own bar outside the page, so it never scrolls away. In the mock it is a fixed overlay that covers the last rows.

## Switch

The option rows are iOS-style switches built on a real `<input type='checkbox' role='switch'>` (`Switch` in `editor.jsx`, styles in `editor.css`): the label click, Space, `disabled` (the shared 0.5 opacity of a disabled row) and the perf harness tap (`.options-row input`) all keep working natively. Approach adapted from the Slider of react-animated-select (`apps/demo/src/components/slider.jsx`, README Slider): stiffness 320, press stretch, rubber feel; no library either way.

- Track: `::before` with `--button` fades in by opacity (compositor) over the `--surface` track. Thumb: `::after`, moved by `translate`, 20 px of travel.
- Spring: `--spring` on `.options` is a CSS `linear()` easing sampled from a damped spring (stiffness 320, damping 22, mass 1, ζ 0.615, 8.6 % overshoot) over `--dur-long` (400 ms, the curve is settled to 0.5 % by then). Damping is 22, not the Slider's 18: with 18 (16 % overshoot) the thumb crossed the track edge by 2 px. The values are generated, not hand-tuned; regenerate them together if the duration changes. `linear()`: Safari 17.2, Chrome 113 (MDN BCD). Reduced motion sets `--dur-long` to 0, so the state changes at once.
- Press stretch (iOS): `data-press` (set on `pointerdown` on the input, not `:active`, which iOS WebKit applies only with touch listeners) widens the thumb from 27 to 34 px toward the centre (`translate` 13 px when on). This animates `width` of the pseudo-element: a `scale` would turn the circle into an ellipse, not a pill; the layout is one absolutely positioned box inside a fixed-size input.
- Drag (`pointer*` handlers on the label, `Switch`): a press on the input that moves more than `SLOP` (4 px) horizontally captures the pointer on the label, sets `data-drag` and writes `--x` (0 … `TRAVEL` 13 px, the travel of the stretched thumb); release sets the value by the side the thumb is on and the thumb springs from where it is. The click that may follow a drag (mouse; touch drags produce none) is cancelled in the capture phase, so a drag never toggles twice; keyboard clicks (`detail` 0) always pass, and any new `pointerdown` resets the gesture. `touch-action: none` on the input keeps the drag from panning. A gesture starts only on an enabled input, checked with `matches(':disabled')`: `input.disabled` is false inside the disabled fieldset (loading, `rendering`), and a drag there would have changed the options of a read-only job.
- Hint text is keyed by its text and fades in when it changes (job arrival: "Already a steady 60 fps").
- Checked in Edge headless (mobile emulation): tap, label click, Space, mouse and touch drags both ways, drag-and-back (no change), Space after a drag, submit payload, disabled in `rendering`. The feel of the spring and the stretch on a phone is for the owner to judge.
