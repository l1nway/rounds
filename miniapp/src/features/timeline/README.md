# timeline

Filmstrip, trim frame with two handles, playhead, clock with the precision mode, frame step and play buttons. `use-drag.js` is the pointer logic shared by the playhead and both handles.

## Fine scrub

Every drag is relative: `value = v0 + (x − x0) · duration / stripWidth · ratio`. A press on the strip first jumps the playhead under the finger, then drags it. Holding still for 400 ms (movement ≤ 6 px resets the timer) lowers `ratio` from 1 to 1/10, another hold to 1/100, with a medium haptic and a re-anchor at the current point, so the value never jumps when the mode changes. The clock line shows the mode and its real step (`Fine · 9.82 ms/px` on a 32 s video at 390 px). In the fine modes each frame boundary crossed gives `selectionChanged`; in the normal mode it would buzz continuously, so it is off there. Hitting a bound gives one `rigid` impact and re-anchors, so dragging back moves at once. The mode resets on release. Keyboard: arrows step one frame, Shift + arrows one second, on the playhead and on each handle.

## Trim bounds

`start` ∈ `[max(0, end − max), min(end − MIN_RANGE, time)]`, `end` ∈ `[max(start + MIN_RANGE, time), min(duration, start + max)]`, playhead ∈ `[start, end]`. `MIN_RANGE` is 1 s (a UI choice, not a backend rule). The handles stop at the selection frame (`time`, the blue dot under the strip) instead of invalidating it: the dot shows where the wall is; selecting on another frame moves it (there is no Clear button, `viewer/README.md`). Dragging a handle seeks the video to it, like the iOS trim. Values are clamped unrounded (so the drag can detect a clamp) and stored rounded to ms.

## Timeline hit areas

The strip itself (`.timeline-scrub`, full width) is the playhead slider for focus, keyboard and accessibility; the visible playhead line has `pointer-events: none`. The handles are separate sliders, 24 px wide (`--hit`) with the 16 px yellow part (`--handle`) drawn by `::before` on the range side. Why: Lighthouse `target-size` failed on the 16 px handle and the 4 px playhead, and a slider inside a slider is invalid (children of `role='slider'` are presentational). The handles sit outside the range, so they never overlap each other; the playhead line is drawn above the trim frame (`z-index: 3` on the line, the scrub layer has no stacking context). The track keeps `touch-action: none` and its `margin-inline` equals the visible handle width, so a handle at 0 or at the end stays inside the padding.

## Filmstrip cells

The sprite (`filmstrip_url`, `tiles` frames in one row) is cut into square cells of the strip height (48 px, `STRIP`, also fed to CSS as `--strip`), each showing the tile nearest to its time, centre-cropped (`background-size` / `background-position` in px from the tile size). Stretching the whole sprite across the strip would distort it at any width. The cell count follows the measured width (`ResizeObserver`). The sprite is decoded (`img.decode()`) before the cells render, then they come in as a wave from left to right: each cell plays `enter` (blur 10 px and scale 1.06 to sharp, `--dur-enter` 700 ms) delayed by its index `--c` × `--wave` (35 ms). Meanwhile the `Sheen` placeholder (`components/README.md`) freezes, fades out over the same 700 ms and is unmounted. Both sit on `--surface`, so the crossfade has no dip. Owner request 2026-10-26: the earlier one-shot 400 ms opacity fade was too abrupt (`IMG_0407.MP4`). Under reduced motion the cells appear at once. The sheen stops (freezes and fades out, no cells) when there is nothing left to wait for: the sprite failed to decode, the job has no `filmstrip_url`, or the video failed (`usePlayer` `failed`, the viewer shows its notice). Owner decision 2026-10-26: an endless shimmer on an error reads as "still loading". Before, a failed decode set `ready` anyway and rendered cells of a broken image.

## Timeline loading

While `job` is null the head (start, clock, end) and the length text are not mounted (owner rule 2026-10-26: nothing invisible stays in the DOM; they used to sit transparent under `data-empty`), so the meaningless `0:00.000` placeholders never exist. Their space is held by the layout, not by an empty node:

- `.timeline` has explicit rows, `calc((var(--clock) + var(--label)) * 1.35) auto auto`, and places the track and the controls in rows 2 and 3, so the head row keeps its height while empty. 1.35 is the html line-height (`index.css`), `--clock` (17 px) and `--label` (12 px) are the font sizes the head itself uses, so the row is the clock line plus the mode line by construction (39.14 px, equal to the mounted head, measured). Change the head's fonts or line-height only through these variables.
- The controls are one grid, `1fr repeat(3, auto) 1fr`, with the first button placed in column 2 (it used to be a spacer `<span/>` plus a `.timeline-buttons` wrapper); the length text, when mounted, falls into the last column. The row height comes from the buttons, so the length text changes nothing.
- When the job arrives the head mounts with its `.enter` class: it plays the entrance (blur and scale, `--i` 1) instead of the old 400 ms opacity fade, after the cascade too, so a late job looks like the rest of the entrance. The length text plays `appear` (`--dur-long`). Measured in the mock (`?job=ingest`, 375 × 667): the timeline stays 163.14 px, and the track and the controls keep their offsets when the head mounts.

The mode line ("Hold still to refine", "Fine · …", "Finest · …") is a `Swap` (`src/README.md`, Swap) in the clock's second row: each label enters and the old one leaves (blur, scale, opacity), and on release the last one leaves and the container is unmounted. The row is reserved by the clock grid (`grid-template-rows: auto 1lh`), not by an invisible node (it was an always-mounted span at `opacity: 0` with a `min-height`). `.timeline-mode` centres the items (`justify-items: center`), so a narrower label does not shift while the wider one leaves. The label changes at most three times per drag (press, two holds), so it is animated; the clock and the length text change every frame or every pointer move and are not. Trade-off: `aria-live` sits on the swap container, which is inserted with its first label. The running clock is its own `memo` component (`Clock`), so only the `<output>` re-renders per frame.

Read-only (`rendering`): the trim frame and its handles are not rendered (it was a frame with a transparent border); the shades show the range. The trim frame, shades and playhead mount with the job and fade in through `@starting-style` (opacity only, so no layout shift; the playhead is already at the selection frame on its first painted frame because the editor seeks in a layout effect). Measured in the mock under slow 4G + CPU ×4: CLS 0 for `?job=done` and `?job=ingest`; before, the playhead mounted at 0 and jumped to the seek target (0.0004).
